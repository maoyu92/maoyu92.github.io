AI编程的「上岗证」：233K星方法论，让18款国产工具真正会干活

工具不是问题，方法是。

一、AI编程的「裸奔」时代

你大概率经历过这个场景——

打开 Claude Code，输入「给用户模块加个批量导出功能」，AI 秒回开始写代码。export async function exportUsers() { ... }，行云流水，一气呵成。

然后你发现：格式不对。没分页。大数据量会 OOM。没考虑权限。连导出格式都没问你。

这不是 AI 的错。是你没给它装「上岗证」。

2026 年的 AI 编程工具，模型能力已经足够强。但大多数开发者缺少的，不是更强的模型，而是一套让 AI 真正按工程方法论干活的工作流。

这就是 superpowers[1] 要解决的问题——GitHub 上 233K+ Star 的 AI 编程方法论框架，目前全球最火的 AI 编程 skills 合集。

而今天的主角，是它的中国增强版——superpowers-zh[2]，一个由中国开发者社区驱动的「方法论汉化 + 国产工具适配 + 中国特色增强」项目。

二、装上之后，AI 变了

来对比一下。

没装 superpowers-zh：

你：给用户模块加个批量导出功能 AI：好的，我来实现……（直接开始写代码）   export async function exportUsers() { ... } 你：等等，格式不对，没分页，大数据量会 OOM……

装了 superpowers-zh：

你：给用户模块加个批量导出功能 AI：在开始实现之前，需要了解几个关键问题：   1. 导出格式是 CSV 还是 Excel？   2. 预计数据量多大？需要异步处理吗？   3. 有权限要求吗？   → 给出 2-3 个方案，确认后再动手

区别在哪？不是模型变聪明了，而是它被注入了一套工程方法论。

superpowers 的核心设计理念是：AI 编程不是「你说需求，AI 写代码」，而是 brainstorming → writing-plans → TDD → systematic-debugging → code-review → verification-before-completion 的完整闭环。

每一步都有对应的 skill 把关，skill 之间彼此衔接，AI 会在合适的节点自动触发对应方法论。

三、20 个 Skill，覆盖开发全流程

superpowers-zh 目前包含 20 个 skill（14 个翻译自上游 + 4 个中国原创 + 2 个上游历史保留），按开发流程可以分为 5 个阶段：

3.1 规划阶段：先想清楚，再动手

  • brainstorming（头脑风暴）：在写任何代码之前，先探索用户意图、需求、设计。强制 AI 在动手前反问需求。

  • writing-plans（编写实现计划）：把需求拆成可执行步骤，强调 YAGNI（You Aren’t Gonna Need It）和 DRY 原则。

  • dispatching-parallel-agents（并行代理调度）：当面对 2 个以上独立任务时，自动调度并行 agent 执行。

3.2 执行阶段：TDD + 子代理驱动

  • test-driven-development（TDD）：先写测试，再写实现。不是「测试后补」，是真红/绿 TDD 循环。

  • subagent-driven-development（子代理驱动开发）：在当前会话中执行包含独立任务的实现计划，由 agent 自主调度子代理完成。

  • executing-plans（执行计划）：在单独会话中执行已写好的实现计划，设有审查检查点。

3.3 调试阶段：系统化，不瞎猜

  • systematic-debugging（系统化调试）：遇到 bug 时，强制先复现、定位根因，再提修复方案。杜绝「猜一个改一下」的瞎试循环。

3.4 审查阶段：合并前必须有证据

  • verification-before-completion（完成前验证）：在宣称工作完成前，必须跑验证命令、拿证据说话。

  • requesting-code-review（发起代码审查）：完成任务后主动发起审查，验证工作成果。

  • receiving-code-review（接收代码审查）：收到审查反馈后，严谨对待，不敷衍附和。

3.5 收尾阶段：规范化的 Git 操作

  • finishing-a-development-branch（收尾开发分支）：提供合并、PR 或清理等结构化选项。

  • using-git-worktrees（Git Worktree 隔离）：通过 git worktree 实现隔离的功能开发环境。

此外，还有 writing-skills（教你写自己的 skill）、mcp-builder（系统化构建 MCP 服务器）、workflow-runner（多角色 YAML 工作流编排）等进阶能力。

四、中国原创 Skill：不止是翻译

superpowers-zh 最大的价值，不是「翻译了英文 prompt」，而是新增了 4 个面向中国开发者的原创 skill：

原创 Skill 解决的问题
chinese-code-review 中文 code review 话术模板、分级标注（必须修复/建议修改/仅供参考）、国内团队常见反模式应对
chinese-commit-conventions Conventional Commits 中文适配、commitlint/husky/commitizen 中文模板
chinese-documentation 中文文档排版规范——中英文空格、全半角标点、术语保留、链接格式
chinese-git-workflow Gitee / Coding.net / 极狐 GitLab / CNB 的 SSH/HTTPS/凭据/CI 接入差异

这四个 skill 解决的是真实痛点：国内团队用 AI 编程工具时，沟通方式、代码规范、Git 平台都和英文社区不同。

比如 code review——英文社区习惯直接说「This is wrong, fix it」，但国内团队需要更委婉的分级话术。superpowers-zh 的 chinese-code-review skill 提供了「必须修复」「建议修改」「仅供参考」三级标注模板，适配国内沟通文化。

再比如 Git 平台——你用的是 Gitee 还是 Coding.net？极狐 GitLab 还是 CNB？每个平台的 SSH 配置、CI/CD 接入方式都不一样。chinese-git-workflow skill 直接给出了配置参考。

五、18 款工具，一条命令

superpowers 上游只支持 6 款工具：Claude Code、Cursor、Codex、OpenCode、Copilot CLI、Gemini CLI。

superpowers-zh 把这个数字拉到了 18 款，新增了：

  • 国产 IDE 类：Trae（字节）、Qwen Code / 通义灵码（阿里）、Kiro

  • 国产 CLI 类：Qoder、OpenClaw、Claw Code

  • 国产 Agent 框架：DeerFlow 2.0（字节）

  • 国际化扩展：Hermes Agent、Windsurf、Aider、Antigravity、VS Code (Copilot)

安装方式也做了大幅简化。上游需要按工具分别执行不同的 marketplace 命令，superpowers-zh 只需要：

npx superpowers-zh

一条命令自动识别项目目录里用的是哪款工具，把 skill 文件装到对应位置。识别不出？加 --tool <name> 显式指定。装完重启工具，AI 生效。

零依赖、纯 Markdown、不联网、不上传代码。 按需触发，零运行时开销。

六、背后的思考：为什么不直接翻译上游？

其实 superpowers-zh 的定位很清晰。作者在 README 里专门列了一张对比表，回答「老被问」的问题：

英文上游 = 方法论内核；中文增强版 = 方法论内核 + 18 款工具一键适配 + 国内 Git/CI 生态 + 中文化表达习惯。

有几个关键差异值得注意：

  1. 上游一般不接受新 skill PR（原文：”we don’t generally accept contributions of new skills”），而 superpowers-zh 欢迎 PR，以中国开发者痛点优先。

  2. 上游是独立迭代，中文版是同步上游 + 国产增量叠加。这意味着上游的 bug 修复和功能更新会同步过来，同时中文版有自己独立的能力演进。

  3. 上游的社区是 Discord，中文版是微信公众号「AI不止语」+ 微信群 + QQ 群。对于国内开发者来说，这显然更方便。

  4. 中文版提供了完整的 CI/CD 示例：GitHub Actions + Gitee Go + Coding CI + 极狐 CI + .cnb.yml，覆盖了国内主流 Git 平台的自动化流水线。

七、配套生态：从零学会 AI 编程

superpowers-zh 不只是给了一套 skill 文件。作者还搭建了完整的配套学习生态：

  • 免费在线书：《AI 编程实战 · 方法论三卷书》，覆盖 10 个 AI 编程工具的完整教程，永久免费。

  • 180 节免费实操课：在 aiOlaOla[3] 上，从零开始学 AI 编程。

  • 实战社区：微信公众号「AI不止语」+ 微信群 + QQ 群。

这套「方法论 + 教程 + 社区」的组合，对于刚接触 AI 编程的开发者来说，是一个完整的入门路径。

八、局限与展望

superpowers-zh 当然不是完美的。

首先，它依赖工具的 skill 机制。 如果某款 AI 编程工具不支持 skill/plugin 系统，superpowers 就装不上。好在目前 18 款主流工具都已支持。

其次，skill 是提示词级别的约束，不是硬性限制。 AI 仍然可能「越狱」——比如在某些场景下跳过 brainstorming 直接写代码。这取决于模型本身对 skill 指令的遵从度。

最后，中国原创 skill 的深度还有提升空间。 目前 4 个国产 skill 偏向配置参考和规范模板，未来如果能加入更多「中国开发场景」的实战方法论（比如微信小程序开发、飞书应用开发、国产数据库适配），价值会更大。

但无论如何，superpowers-zh 已经迈出了关键一步：让 AI 编程方法论这个「基础设施」覆盖到中国开发者的工具箱和开发生态。

九、写在最后

AI 编程工具这两年爆发式增长，Claude Code、Cursor、Codex、Gemini CLI、通义灵码……工具越来越多，模型越来越强。

但一个尴尬的事实是：大多数开发者并没有因为工具变强而效率翻倍。 原因是——工具强了，但使用方式没变。还是「你说需求，AI 写代码」的老套路。

superpowers 要解决的就是这个「最后一公里」问题：让 AI 不仅会写代码，更会按工程方法论干活。

而 superpowers-zh 在此基础上，让这套方法论能在中国开发者的工具箱里跑起来。

一条命令，20 个 skill，覆盖 18 款工具。免费、开源、零依赖。

npx superpowers-zh

装好之后，你的 AI 编程工具，才算真正「上岗」了。
