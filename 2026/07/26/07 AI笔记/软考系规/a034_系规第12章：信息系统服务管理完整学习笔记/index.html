系规第12章：信息系统服务管理完整学习笔记

学习目标

信息系统服务管理不是“出了故障再修”，而是从服务目录、需求和SLA开始，设计人员、资源、技术、过程，经营客户与成本，安全退役，并通过测量、回顾和改进形成全生命周期闭环。

这是“系规学习”的第9期。第12章是全书最密集的章节之一，综合题清单多、案例题权重高，也能支撑服务管理类论文。本文按12.1—12.5完整展开。

本章地图：五阶段贯穿服务全生命周期

  1. 服务战略规划：明确能提供什么、客户要什么、承诺到什么级别。
  2. 服务设计实现：选择服务模式，设计人员、资源、技术、过程。
  3. 服务运营提升：经营关系、营销服务、度量成本并管理收支。
  4. 服务退役终止：沟通移交、控制风险、回收资源、处置信息。
  5. 持续改进与监督：风险、测量、质量、回顾和改进贯穿始终。

一条贯穿全章的逻辑

目录定义能力 → 需求表达期望 → SLA形成承诺 → 四要素保障交付 → 运营数据证明结果 → 退役安全收尾 → 测量回顾驱动改进。

12.1 服务战略规划：先把服务承诺说清楚

12.1.1 三项规划设计活动

  1. 服务目录管理
  2. 服务需求识别
  3. 服务级别设计。

需方结合目录提出需求，供方兼顾成本与定价设计服务级别，最终形成SLA、OLA和支持合同。

12.1.2 服务目录管理

服务目录是供方所提供服务的集中、统一信息源，用于管理客户期望，并支撑需求识别和协议制定。

六个步骤：

  1. 成立管理小组：至少包括市场销售、系统规划管理、服务工程人员
  2. 列举服务清单：包含正在提供和准备提供的服务
  3. 确定服务类别与代码：按技术对象或服务性质分类并唯一编码
  4. 编制服务详述：描述内容、目标、级别、方式和技术实现
  5. 评审并发布：形成交付和管理基准
  6. 完善目录：随市场需求、能力和技术变化持续更新。

口诀：成、列、类、述、发、完。

12.1.3 六类服务需求

  1. 可用性需求：业务能容忍多久中断，中断造成什么损失
  2. 连续性需求：重大中断后如何维持和恢复关键业务
  3. 服务能力需求：当前和未来容量、性能与响应能力
  4. 信息安全需求：机密性、完整性、可用性
  5. 价格需求：设备、软件、人力、第三方支持、管理等成本与定价
  6. 服务报告需求：面向不同受众报告什么、何时报告、采用何种格式。

三个可用性指标

  • MTBF平均无故障时间＝系统运行时间÷故障次数，越长越可靠
  • MTTR平均故障修复时间＝故障耗时÷故障次数，越短越易恢复
  • MTBSI平均故障间隔＝MTBF＋MTTR，两次相邻事件间隔。

串联系统可靠性为各组件可靠性相乘；并联系统可靠性为1－各组件同时失败的概率。

12.1.4 SLA、OLA和UC

文档 关系与作用
SLA服务级别协议 供方与客户之间，约定质量、性能、职责和目标，具有正式约束
OLA运营级别协议 供方内部部门之间，分解支撑SLA所需的后台责任
UC支持合同 与外部供方相关的正式合同，在服务要求上增加法律责任、权利和义务

SLA目标必须适度、可测、可承担成本。只写“保障稳定、及时响应”而没有指标、时间窗、例外和责任，不是可执行SLA。

12.2 服务设计实现：模式＋人员、资源、技术、过程

12.2.1 四种服务方式

  • 远程集中监控
  • 远程技术支持
  • 上门技术支持
  • 驻场技术支持。

选择时检查三点：与可用性、连续性、安全需求一致；供方人员资源与模式匹配；能够随需求变化组合调整。

12.2.2 人员要素

设计范围包括岗位职责、人员绩效和培训，目标是让组织、数量、能力、稳定性与连续性满足服务。

三类岗位：

  • 管理岗：管理客户需求、服务过程和结果
  • 技术支持岗：提供专业诊断与解决能力
  • 操作岗：按规范和手册执行服务台、监控、值守等交付活动。

绩效方案五步：

  1. 确定差异化指标
  2. 明确信息来源
  3. 制定计算方法
  4. 定义考核周期
  5. 设计公开、反馈和激励策略。

培训活动包括需求分析、内容设计、实施过程、效果评价。内容涵盖管理、技术、工具、过程、交付与应急；形式可用授课、实操、研讨、在线学习等。

12.2.3 资源要素

  1. 服务工具：监控工具、过程管理工具、自动化和安全等其他工具
  2. 服务台：服务职能而非服务过程，是需方与供方的统一联系点
  3. 备件库：设计响应级别、供应商、出入库与可用性管理
  4. 知识库：沉淀常见问题、原因和解决方法，支持添加、更新、查询、共享和生命周期管理。

服务台要有统一渠道、专人受理，并整合接收、记录、分类、跟踪、反馈、监督和考核机制。

12.2.4 技术要素

从三方面设计：

  • 技术研发：识别技术储备和新技术应用，估算成本并编制预算
  • 发现问题的技术：明确监控对象、指标、阈值，建设仿真测试环境
  • 解决问题的技术：制定标准操作流程、验证方案并完成知识转移。

监控不是工具装上就完成，必须先从业务和SLA反推对象、阈值、告警分级和处置动作。

12.2.5 八个管理过程

  1. 服务级别管理：目录、SLA、考核和改进
  2. 服务报告管理：建立、审批、分发、归档报告
  3. 事件管理：尽快恢复正常服务，受理—分类分级—支持—诊断—解决—跟踪—关闭
  4. 问题管理：识别事件根因并防止重复发生
  5. 配置管理：识别和维护配置项及其关系，保证配置数据可靠
  6. 变更管理：评估、批准、计划和控制变更风险
  7. 发布管理：规划、构建、测试、部署和验证发布
  8. 信息安全管理：按安全要求控制服务全过程。

事件管理关注“尽快恢复”，问题管理关注“找到根因”；不能因为事件关闭就停止根因分析。

12.3 服务运营提升：不仅交付服务，还要经营关系和成本

12.3.1 三类业务关系

业务关系管理包括客户关系、供应商关系和第三方关系。

客户关系活动：

  • 定期沟通与日常沟通
  • 高层拜访
  • 投诉和表扬管理
  • Case by Case与公开满意度调查
  • 在不影响合同、贴合需求、成本可控且自身有能力的前提下提供增值服务。

供应商管理要建立互信协作，明确评价、绩效、风险、升级和替代机制；第三方关系要明确接口、责任和信息传递，防止多方服务出现责任空档。

12.3.2 服务营销四阶段

  1. 启动准备：知识、客户、产品、现有服务和营销计划准备
  2. 调研交流：访谈高层和业务人员，识别真实需求并形成方案
  3. 能力展示：展示产品、案例与服务能力，持续沟通
  4. 服务达成：谈判并签订协议，转入持续服务。

营销不是夸大能力，而是让客户需求与供方可交付的目录、级别、成本相匹配。

12.3.3 四类服务成本

  1. 直接人力成本：项目人员报酬、社保规费、福利
  2. 直接非人力成本：特定项目的办公、差旅、培训、业务、采购、租赁
  3. 间接人力成本：管理、PMO、配置与质量保证等非项目人员分摊
  4. 间接非人力成本：不因某个项目终止而消失的通用场地、设备、软件等分摊。

判断关键：能否直接、唯一归属于该项目；项目结束后费用是否仍存在。

12.3.4 预算、核算和结算

预算包括收入和开支，作用是计划资金、协调活动、分配资源、授权开支、控制费用和评价效果。

预算三步：

  1. 识别收入项与开支项
  2. 划分项目执行阶段
  3. 形成预算表。

执行中依据人员、服务台、备件、工具、知识库、研发和过程管理等开支进行核算；结算则依据合同、服务结果、验收与核算数据确认应收应付。预算是计划，核算记录实际，结算完成对外或内部资金确认。

12.3.5 外包六项收益

  • 成本效益
  • 效率提升
  • 降低风险
  • 专注主营业务
  • 管理简单
  • 提升满意度。

但外包不等于转移最终责任。需方仍要保留治理、供应商管理、数据安全、连续性和退出能力。

12.4 服务退役终止：服务结束不等于责任瞬间消失

12.4.1 四类沟通会议

  1. 服务终止计划编制会议
  2. 服务终止计划评审会议
  3. 移交会议
  4. 经验交流会。

终止计划应包含条件、目标、成功要素、角色职责、约束风险、里程碑交付物、活动分解、完成标准、终止时间、服务接口处理、安全审查，以及遗留事件、问题和变更的处置。

12.4.2 四类退役风险

  1. 数据风险：泄露、篡改、滥用、违规传输、非法访问
  2. 业务连续性风险：人员提前流失、交接不完整、继任团队理解偏差
  3. 法律法规风险：合同、知识产权、数据和监管义务未清
  4. 信息安全风险：账户权限未撤销、介质和资料未清理、保密责任中断。

应建立风险清单、评估等级，对高风险制定责任人、措施、触发条件和验证方式。

12.4.3 资源回收

  • 文件归档：日志、计划、函件、会议、报告、合同和技术文档
  • 财务资源：结清账目并撤销项目编码
  • 人力资源：按计划释放、重新分配并保障关键人员交接
  • 基础设施：回收设备、工具、许可证、场地和备件，恢复可用状态。

12.4.4 信息处置

先明确服务数据和文档所有权，再转移或清除；必要时清除或销毁介质。

信息处理步骤：

  1. 建立资产或介质清单
  2. 按敏感程度、所有权和法规制定方案
  3. 受控执行并记录参与人、方式、位置和结果
  4. 检查残余信息并由相关方确认。

删除文件名或普通格式化通常不足以安全清除敏感数据，应采用符合要求的方法并保留证据。

12.5 持续改进与监督：用数据证明服务真的变好

持续改进贯穿全生命周期，包括服务风险管理、测量、质量管理、回顾和改进。

12.5.1 服务风险管理

风险来源包括人员、技术、资源、过程和其他方面。管理活动涵盖策划、组织、领导、协调和控制，并应动态维护风险清单。

12.5.2 服务测量

目标是监视、测量和评审服务及管理目标，识别与计划的差距，为改进提供依据。测量对象覆盖：

  • 人员：能力、培训、招聘、绩效、储备、职责、工作量和稳定性
  • 资源：工具、服务台、知识库、备件库
  • 技术：研发、监控、测试、解决问题和知识转移能力
  • 过程：SLA、报告、事件、问题、配置、变更、发布和安全过程。

测量必须定义指标口径、数据源、频率、责任人、目标值和异常处置，避免只统计“看起来容易收集”的数据。

12.5.3 服务质量管理

GB/T 33850服务质量模型的五类特性：

  1. 安全性
  2. 可靠性
  3. 响应性
  4. 有形性
  5. 友好性。

评价四步：确定需求、指标选型、实施评价、结果分级。

质量管理活动：

  • 质量策划：目标、职责权限、时间和策划文件
  • 质量检查：满意度、质量保证、内审、管理评审、日常检查和质量培训
  • 质量改进：根据问题确定方向、目标、措施并跟踪效果。

12.5.4 服务回顾

服务回顾把测量数据转化为共同认识。四级机制：

  • 一级：重大或特殊事件，按需
  • 二级：项目月度例会
  • 三级：季度运营回顾
  • 四级：年度合作回顾。

与客户回顾合同、目标、SLA、绩效、满意度、范围、需求变化和行动计划；团队内部回顾计划、疑难工单、问题、KPI和下一周期安排。重大项目还应复盘。

12.5.5 服务改进

改进生命周期：

  1. 改进设计：定义可测目标、识别输入和措施、编制计划
  2. 改进实施：按责任、资源、时间和风险执行并记录
  3. 改进验证：比较改进前后指标，确认目标和客户价值。

改进来源包括测量回顾、客户差距、投诉满意度、审核评审、KPI趋势、员工建议、业务技术变化和过程反馈。

三门考试怎么用

综合题

重点背：目录六步、需求六类、SLA/OLA/UC、PTRP四要素、四种服务模式、八个过程、成本四类、退役四风险、质量五特性、改进三阶段。

案例题

按生命周期扫描：战略阶段是否有目录、需求和SLA；设计是否匹配PTRP；运营是否管关系、成本和供应商；退役是否有计划、风险、回收与信息处置；持续改进是否有指标、回顾、计划和验证。

示例：服务台只记录电话，没有统一分类、跟踪、升级和反馈，导致请求丢失且无法度量；应建立统一联系点和工单流程，定义分级、升级、SLA计时、满意度与关闭验证。

论文

可按“背景需求—服务战略—服务模式—PTRP设计—运营与关系—测量质量—改进成效”展开。若写外包服务，应补供方管理、数据安全、连续性和退出机制。

闭卷自测

  1. 服务目录管理六步是什么？
  2. 六类服务需求及MTBF、MTTR、MTBSI含义是什么？
  3. SLA、OLA、UC如何区分？
  4. 人员、资源、技术、过程分别设计什么？
  5. 八个服务管理过程是什么？事件和问题管理有何区别？
  6. 业务关系三类、服务营销四阶段是什么？
  7. 四类成本和预算三步是什么？
  8. 服务退役四类风险、四类资源回收是什么？
  9. 服务质量五特性和四级回顾机制是什么？
  10. 服务改进三阶段是什么？

写在最后

第12章不是25张孤立清单，而是一条完整链路：

以需求和SLA定义承诺，以PTRP设计能力，以关系与成本经营服务，以退役控制尾部风险，以测量回顾验证并持续改进。

第一轮先掌握五阶段和关键清单；第二轮再按案例把每个问题定位到生命周期阶段、要素和过程。
