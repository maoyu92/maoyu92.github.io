复习建议

学习目标

技术研发的价值不在于“做出了多少工具”，而在于能否把新方法、新规范和新工具转化为稳定的服务能力。研发需要规划、实施和监控，更需要测试、培训、知识转移、持续跟踪；形成的创新成果还要通过知识产权管理实现保护与运用。

这是“系规学习”的第12期。第15章有三条主线：研发什么、怎样把成果用起来、怎样保护和经营成果。综合题考角色、过程和分类，案例题高频考成果应用细节，知识产权部分也能支撑论文。

01PART

本章地图：研发—应用—保护，技术价值才真正闭环

LEARNING · KEY POINTS

技术既可能是工具设备等硬件，也可能是工艺、方法、规则等无形知识，还可能是设计图纸、信息资料等具有载体的成果，这就是技术的多元性。

技术研发的两个目的：

1使用研发成果提高信息系统服务效率和服务质量；

2研究组织相关技术和行业新技术，并将其用于服务产品和服务工具。

— 技术研发价值闭环

全章逻辑：

需求与战略决定研发方向 → 组织角色和过程保证产出 → 评定、验证和知识转移促进应用 → 跟踪效果并优化 → 知识产权获取、维护、运用和保护创新价值。

02PART

15.1 技术研发管理：先明确研发什么、谁负责、怎样管

LEARNING · KEY POINTS

五类研发范围

1运行相关技术：掌握服务对象本身的技术，是提供服务的基本能力；

2技术规范研发：服务规范规定应达到的质量水准，服务提供规范规定用什么方法达到该水准；

3发现与解决问题技术：监控采集、诊断分析、处理方法、判断方法、脚本、工具、手册和风险控制；

4运行维护工具研发：监控工具、过程管理工具和专用工具；

5信息系统服务产品研发：把服务有形化、标准化并融入自身核心能力与差异化设计。

可感知属性是服务营销、交付和成本核算的基础。研发服务产品往往需要多个部门共同参与。

技术研发管理六项内容

1研发团队：根据课题跨部门组建，必要时引入需方或供应商；

2研发过程：将常规或可形成常规的环节程序化、制度化；

3研发成本：减少不必要开支，而不是简单压缩研发规模；

4研发项目：研发以项目为导向，需要运用项目管理；

5研发绩效：关注项目难度、研发效率和研发质量；

6研发风险：通过制度和控制措施将风险降至可接受水平。

口诀：团、过、成、项、绩、险。有些案例资料只写前五项，考试以教材六项为准。

五类角色

角色 主要职责
技术研发决策负责人 承担技术研发总体决策
技术研发需求负责人 负责需求调研和研发成果应用
技术研发负责人 负责研发规划、过程组织和成果应用支持
质量管理负责人 建设、实施、检查和改进质量管理体系
财务负责人 审查投入产出、筹措费用、度量财务回报

易错点：需求负责人不只“提需求”，还负责成果应用；研发负责人则组织研发并提供应用支持。

四个管理过程

1规划过程：需求调研、确定目标、制定方案、投入产出分析、形成立项报告、评审发布；

2实施过程：制订实施计划、组织研发、产出成果；

3监控过程：通过周报、月报、里程碑总结、质量审计、内审和管理评审监控；

4应用过程：将成果推广到服务中，研发团队提供培训和支持，交付负责人主动使用。

口诀：规、实、监、用。不是项目管理的“规划—执行—监控—收尾”，最后一个是应用。

三项基础条件

1建立鼓励创新、适合研发的环境，采用弹性而目标化的管理，既不扼杀创意，也要求实质成果；

2将市场观念融入研发，让市场人员参与，使有限资源产出更高价值；

3制定并掌握研发策略，指导有限资源规划使用，追求更短时间和更高效益。

六类研发管理要点

服务产品研发

●定位：满足需方购买需求和供方业务拓展需求；

●队伍：通常是跨部门虚拟团队，由产品经理负责研发、推广和团队管理；

●成果：服务目录、服务交付方式、服务质量管理；

●延伸：常延伸到售前支持和交付支持。

信息系统服务规范研发

服务规范化是服务产品化的前提。研发团队一般由质量管理负责人、资深技术专家、资深需方服务经理组成。

过程：编写规范 → 测试演练 → 定稿 → 评审 → 交付部门执行 → 质量部门监督 → 根据问题定期更新。

产出包括工作指南、过程管理规范、技术手册、故障处理手册。过程规范通常用普通办公环境即可，技术规范需要实验环境验证。

服务工具研发

●内部工具：服务过程管理工具，团队由交付管理人员和软件人员组成；

●业务工具：监控工具和专用工具，团队由交付技术人员和软件开发人员组成；

●过程：通常以软件为主，按需求、设计、编码、测试开展；

●环境：开发环境＋测试环境；

●产出：发布包和使用手册、工具介绍文档、需求设计文档及源代码。

发现与解决问题技术

发现问题包括信息采集监控、诊断分析；解决问题包括处理方法手段和解决结果判断方法。

研发团队一般由高级运维工程师和技术专家组成。工具类走工具研发过程；文档类经编写、测试演练、定稿、评审后上传知识库并发布，由质量部门监督。

新技术研究

分为支撑需方业务的新技术和支撑服务的新技术。资深技术专家持续跟踪、分析应用前景并积累知识，时机成熟后内部传递。产出包括应用前景分析报告、技术文档和培训教材。

— 六类技术研发对象

03PART

15.2.1 研发成果应用：先判断、再验证、后推广

LEARNING · KEY POINTS

新技术、新系统或新工具应先进行技术评定，形成评定报告；审批后开展测试；证明有效后形成验收报告，再进入推广阶段。

六项应用管理要点

1技术风险与机遇：分析有利和不利影响，将不利因素纳入风险管理并控制；

2判断与选择：结构化分析利弊，识别不可逾越的困难、所需资源和实现条件；

3技术验证：对性价比高但风险较大的应用进行验证，必要时开发原型；

4技术决策：选择技术方向、服务技术和工具技术，并完成可行性分析；

5技术应用：把技术转化为人员能力、服务工具、客户价值和可复用知识；

6技术实现跟踪管理：定期评估状态，跟踪问题，及时终止不适用技术，分级明确责任并随服务组合调整规划。

口诀：险、判、验、决、用、跟。

案例中“当前存在无法克服的技术瓶颈，需要分析所需资源和条件”属于判断与选择；“开发原型验证效果”属于技术验证；“使用一段时间后评价并及时停止”属于跟踪管理。

技术应用不是简单交接

完整应用至少包括：

●人员会用：培训与知识转移；

●工具可用：稳定、可维护、可支持；

●服务能用：嵌入交付过程和服务组合；

●客户受益：产生业务绩效和服务价值；

●组织可复用：知识化、文档化并持续更新。

04PART

15.2.2 八类主要应用：案例题的核心考区

LEARNING · KEY POINTS

知识转移

完备的知识转移可以提高技术支撑能力、降低风险和成本、提升效率。内容分四类：

1历史运维资料：工作界面、职责说明、内外部支持信息；

2基础架构资料：部署和物理拓扑、架构配置、备份恢复、应急容灾、日常运维手册；

3应用系统资料：测试报告、用户手册、需求设计、安装配置、版本及依赖和已知错误；

4业务资料：业务架构图、业务流程、业务场景、培训材料、业务FAQ和诊断文档。

易错点：业务架构图属于业务资料，不属于基础架构资料；人员职责说明属于历史运维资料。

应急响应预案与演练

应急预案用于重大系统性故障、区域或全国业务中断、重大数据损失、安全事件等场景，包括自然灾害、网络通信、供电机房、数据库与中间件、网络攻击与病毒、应用重大故障等。

四项演练原则：

1结合实际、合理定位：明确目的，按资源确定方式和规模；

2着眼实战、讲求实效：提升指挥协调和实战能力，并评估整改；

3精心组织、确保安全：科学设计并严格执行安全措施；

4统筹规划、厉行节约：充分利用现有资源，提高演练效益。

演练是对预案或灾备方案进行仿真，需要时相关方共同参与并投入资源；推演则通过沙盘或模拟研讨可能情况。

SOP标准操作规范

SOP以统一格式描述某项工作的标准步骤和要求，精髓是把关键控制点细化、量化。

作用：

●将经验沉淀为标准文件，防止人员流动造成技术流失；

●让操作人员经短期培训快速掌握技术；

●树立专业服务形象；

●推动流程规范化、条理化、标准化和操作简明化；

●是系统规划与管理师基本而有效的技术管理手段。

五项编写原则：

1在人力、财力、物力允许范围内可实现；

2服务人员都能看懂且理解一致；

3效率高、成本低，并识别关键风险点；

4正式发布前经过测试和评价；

5能随业务和技术发展快速迭代。

技术手册发布

正确顺序是：审核 → 存档 → 发放。

先确保内容正确和批准，再保留受控基线，最后向使用者发放。案例中“审核—发放—存档”顺序错误。

测试环境

按规划设计明确测试目标，用模拟工具还原真实场景并执行测试，验证技术可行性和可靠性。测试环境的价值是提高供需双方信心、规避潜在缺陷、降低突发事件发生率。

培训、演练与持续优化

成果培训包括知识性成果、工具类成果、应急预案和解决方案手册；演练或推演验证内容是否能在真实压力下使用；评价和实践反馈则驱动新一轮开发，并配置相应预算。

— 研发成果落地路径

05PART

15.3 知识产权管理：让创新成果可确认、可运用、可保护

LEARNING · KEY POINTS

知识产权包括专利权、商标权、著作权、商业秘密等。管理需求包括研发创新、提高附加值和市场份额、防范风险保障经营、提升效率和效益。

四项指导原则

1战略导向：经营、创新和知识产权战略相互支撑；

2领导重视：最高管理者全面负责并确保合规义务履行；

3全员参与：所有业务领域和人员都遵守合规义务；

4全程管理：在产品和服务全生命周期管理知识产权和风险。

最高管理者是第一责任人。知识产权管理机构负责识别和分配合规义务、提供建议、制订实施计划、日常统筹、监督考核和重大项目专利导航；其他部门负责落实相关工作。

过程策划

1确定目标、实现方法和所需资源；

2确定知识产权类型和管理重点；

3分类型制定获取、维护、运用、保护的控制要求；

4保持和保留成文信息；

5保证内部、外部有效沟通。

获取

●按目标制定不同类型的获取计划；

●建立审核流程，防止非正常专利申请、非法获取商业秘密、剽窃作品；

●专利申请前检索分析，评价授权前景和价值并保障发明人署名；

●适时登记作品，明确职务、委托和合作作品权属，保留创作记录；

●通过遴选和密级划分确定商业秘密范围、接触范围、流转和存证要求。

维护

1建立分类档案并日常维护；

2管理权属变更与放弃；

3披露相关会计信息；

4建立会计核算档案，有条件时核算成本和产出效益；

5保管宣传、广告、包装、说明书等相关资料；

6分级管理；

7保留维护成文信息。

运用

五类方式：实施和使用、许可和转让、投融资、企业重组、标准化。

保护

●风险管理：避免侵犯他人权利，持续监控产品工艺，纳入组织风险管理；管理涉密人员、载体、设备、区域和信息；对外披露前开展知识产权与保密审查；

●争议处理：发现侵权后选择自力、行政或司法救济，并比较协商、诉讼、仲裁、调解的影响。

评价、审核与改进

组织应监控和审查体系绩效，分析数据并评价：

●知识产权价值实现符合性；

●合规管理体系绩效和有效性；

●策划实施情况；

●合规监测结果；

●风险机遇措施有效性；

●外部供方绩效；

●体系改进需求。

06PART

三门考试用法：把清单变成能落地的答案

LEARNING · KEY POINTS

综合题

重点识别：六项管理内容、五类角色、四个管理过程、六类研发对象、应用六要点、知识转移四类资料、演练四原则、SOP五原则、知识产权四原则及获取维护运用保护。

案例题

常见整改模板：

1需求与使用脱节：让需求负责人、运维和需方参与；

2上线不稳定：搭建测试环境，技术评定、原型验证和验收；

3成果没人会用：补培训、知识转移、技术手册和应用支持；

4手册与现场不符：审核—存档—发放，建立版本和定期更新；

5新技术未形成能力：嵌入服务流程与工具，跟踪效果；

6成本失控：投入产出分析、预算与里程碑监控；

7知识产权风险：明确权属、申请前检索、保密分级和对外披露审查。

论文

可按“研发背景与目标—组织与职责—规划实施监控—成果验证和应用—知识转移—成效评价—知识产权保护—持续改进”组织。成果必须写到服务效率、质量、风险或客户价值的变化，不能停在“完成研发”。

SUMMARY · REVIEW SMARTER

第15章的骨架可以压缩成一句话：

研发不是交付一个工具，而是用组织、过程和控制产生可靠成果，再通过验证、培训、知识转移和跟踪把成果变成服务能力，最后用知识产权管理保护并经营创新价值。
