把自然语言变成架构图：drawio-skill EP.3 深度解读

你不需要再对着空白画布想第一根线怎么画了。现在可以把代码、配置和描述直接“丢”给 Agent，让它替你生成架构图。

这不是一个“画图脚本”

很多人对 drawio-skill 的第一印象还停留在“输入文字，出个图”。

但到 EP.3 这个版本，这个项目的目标已经变了：它不再只是一个自然语言绘图工具，而是一个 面向工程交付的架构图生成器。关键证据是：三个月里从 v1.4 推进到 v1.34，现在是 v2.0/v2.1；脚本从个位数增长到 37 个；测试从几十条变成 128 条；GitHub Star 已经过 5800。

更关键的是，它的输出对象从“一张图”扩展成了四类工程资产：

  • 可交付 PNG / SVG / PDF / JPG

  • 可继续编辑的 .drawio

  • 可嵌入文档和流程的 Markdown / Mermaid

  • 可汇报使用的 PPT / HTML 导出链路

也就是说，它的价值不是“画得好看”，而是“从工程事实生成图，再回到工程流程里继续用”。

为什么我说它很适合当前工作流

如果你日常会做这几件事，drawio-skill 的回报会很高：

  • 读一个新仓库，需要画模块依赖图或类继承图

  • 给团队讲部署结构，需要把 K8s / docker-compose 还原成图

  • 维护数据库，需要定期更新 ER 图

  • 写方案或周报，需要一张能继续修改的架构图

  • 做技术分享，需要把流程图、系统图导出成 PPT 或 PDF

过去这些事的共同点是：你手里明明有事实来源，但画图本身占掉大量时间。drawio-skill 的核心，就是把“已有事实 → 可交付架构图”这段过程尽量自动化。

EP.3 真正新增的三条能力线

这次更新不是简单加模板，而是明显分成了三条能力线。

1. 从代码和基础设施直接生图

这是这次最实用的部分。项目现在可以直接读取多种工程输入：

  • 代码结构：Python、JS/TS、Go、Rust 的模块依赖或 Python 类继承

  • 基础设施：Terraform、Kubernetes、docker-compose

  • 数据层：SQL DDL，可直接生成带主外键的 ER 图

而且它不只是“列出组件”，还会尽量还原连接关系。比如从 K8s 清单里抽 selector、volume mount、role ARN 这类真实引用，再生成连线；从 Terraform 配置里提取资源关系，自动匹配 AWS / Azure / GCP / K8s 官方图标。

这意味着你不需要为了画一张部署图，再去手工维护一套架构说明。

2. 让图更像工程产物，而不是示意图

EP.3 在“专业图”这部分补了很多细节。

比如现在支持 11 类图模板：UML Class、Sequence、C4、Architecture、ML/Deep Learning、Flowchart、SysML、BPMN、Network Topology、Cross-Functional Swimlane、ER Diagram。C4 还支持多页下钻，从 System Context 到 Container 再到 Component。

它还能做一件很实用的事：把白板照片、PNG、Visio 截图转成可编辑的 .drawio。也就是你团队里那些“拍照流传下来的架构图”，现在有机会二次编辑了。

另外还有形状搜索和 AI 大模型品牌图标库：前者能在 10000+ 官方图形里找到准确图标，避免继续画空白框；后者给了 321 个 AI/大模型相关 logo 和 18 个数据存储品牌 logo，画 RAG/Agent 架构图时明显更方便。

3. 图生成后的工作流

很多工具能生成图，但很少关心这张图后面怎么继续用。EP.3 这里补得比较实在：

  • 导出到 PNG / SVG / PDF / JPG

  • 导出到 Mermaid / Markdown

  • 导出到 PPT / 可交互 HTML

  • 把静态图做成可点击排障 runbook

  • 把静态图做成 buildup 动画

  • 把几百节点压成“董事会版一页摘要”，还能继续下钻

  • 把 git 历史变成架构演进时间轴

  • PR diff 自动输出改前 / 改后 / 彩色差异图

如果只看其中一点，最有普适性的其实是 PR 自动 diff 图和 runbook 可点击流程图。前者解决代码评审里的“改了哪里、结构怎么动”；后者解决运维和 On-call 里的“看到问题先看哪一层”。

一个值得关注的细节：drawiodiff

这次最让我感兴趣的能力，其实是 drawiodiff：拿声明架构和运行架构做漂移检测。

具体来说，它可以比较“你认为系统长什么样”和“它实际上长什么样”，并用颜色标记差异：

  • 绿色：新增

  • 红色：删除

  • 橙色：改动

对当前很多团队来说，架构漂移是一个真实痛点。文档长期不更新，新人看文档、老鸟看线上，两边经常不一致。drawiodiff 这类能力虽然还不够完整，但方向是对的：让图不只是展示层产物，而是变成可比较、可审计的工程对象。

它的真实使用方式

drawio-skill 现在的定位不是普通用户绘图软件，而是 Agent Skill / 工程插件。它支持 Claude Code、Cursor、Copilot、OpenClaw、Codex、Autohand Code、Hermes 等工具，而且官方强调一点：不需要额外搭 MCP server，也不需要常驻后台，一个 SKILL.md 就能跑。

这很重要。很多自动化能力之所以难落地，是因为运行成本太高。这个项目选择保持“单技能、零守护进程”，对日常嵌入工作流更友好。

适用边界

当然，它不是万能图工具。

如果你要的是完美排版、复杂品牌级视觉、或是高定制化汇报长图，它不一定比专业设计师输出更合适。它的优势是：面对工程场景时速度快、可重复、能接续编辑、能进入交付流程。

换句话说，它不是用来替代专业制图，而是用来替代“工程师为了出一张架构图而中断工作流”这件事。

写在最后

drawio-skill EP.3 真正有价值的信号是：架构图正在从“人工产物”变成“工程产物”。代码变了，图可以重新生成；部署变了，图可以重新生成；数据库变了，ER 图也可以重新生成；PR 提交了，diff 图可以直接贴进评审。

这才是它值得放进稍后学习清单的原因。

如果你日常会读代码、看部署、写方案、做评审，这张图很可能已经值得装进工具箱了。
