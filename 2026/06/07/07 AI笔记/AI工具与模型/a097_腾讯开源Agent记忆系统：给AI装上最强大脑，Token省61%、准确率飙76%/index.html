腾讯开源Agent记忆系统：给AI装上最强大脑，Token省61%、准确率飙76%

记忆不是让 AI 记住一切，而是让人不用重复说一遍。

一、AI Agent 的”失忆症”

你有没有这种体验？

花了半小时跟 AI 助手解释清楚项目背景、代码规范、输出格式，它终于”懂了”。结果第二天新开一个会话——

它全忘了。

从头来过。

这不是 AI 笨，而是当前 Agent 架构的一个结构性缺陷：LLM 本质是无状态的。每次推理调用，它只认当前上下文窗口里的东西。窗口之外？不存在。

更致命的是，当你试图用”全量记忆”来解决这个问题——把所有历史对话都塞进上下文——Token 消耗会呈指数级膨胀。一个连续跑 50 个任务的长会话，Token 烧掉几百万是常态，模型注意力也被稀释到几乎为零。

要么失忆，要么烧钱。 这就是 AI Agent 面临的”记忆困境”。

2026 年 5 月，腾讯云数据库团队开源了 **TencentDB Agent Memory[1]**，给出了第三条路。

二、四层记忆金字塔：像人一样”分层记”

TencentDB Agent Memory 的核心设计哲学用一句话概括：

记忆不该是平铺直叙的，应该有层次。

就像人脑不会记住每一顿饭吃了什么，但会记住某个重要晚宴的关键细节。Agent 的记忆也应该是分层的——该忘的忘，该记的记。

这套系统把记忆分成 4 个层级：

┌──────────────────────────────────┐ │ L3 Persona — 用户画像 (Markdown) │ ← 最抽象 │ 长期偏好 · 工作习惯 · 回复风格 │ └──────────────┬───────────────────┘ │ 抽象/细化 ┌──────────────┴───────────────────┐ │ L2 Scenario — 场景块 (Markdown) │ │ 常见解决方案 · 标准化SOP · 调用模式 │ └──────────────┬───────────────────┘ │ ┌──────────────┴───────────────────┐ │ L1 Atom — 原子事实 (数据库全文检索) │ │ 关键信息点 · 知识片段 · 结构化事实 │ └──────────────┴───────────────────┘ │ ┌──────────────┴───────────────────┐ │ L0 Conversation — 原始对话 (数据库)│ ← 最具体 │ 完整历史对话 · 工具输出 · 错误日志 │ └──────────────────────────────────┘

四层记忆金字塔：从原始对话到用户画像，层层抽象，全链路可追溯

关键设计：

  • L0 原始对话层：全量保留每一轮交互，作为”证据链”的最底层

  • L1 原子记忆层：自动提取事实、偏好、约束、阶段结论

  • L2 场景归纳层：按任务自动聚合，形成”常见解决方案”

  • L3 用户画像层：持续蒸馏出稳定的长期画像

层与层之间通过提取→聚合→蒸馏的管道连接。任何一层都可以独立升级或替换。

最精妙的是：每一层都可以向上溯源——从”用户偏好”一路追溯到”原始对话”，保证全链路可追溯。这意味着 Agent 做出的每个判断都有”证据链”支撑，不是凭空捏造。

三、符号化短期记忆：用 Mermaid 代替日志

分层架构解决了”跨会话失忆”，但还有一个更紧迫的问题：单次长任务中的信息过载。

跑过长任务的朋友都知道，Agent 最大的 Token 消耗来自哪里？中间日志。

搜索结果、代码片段、错误追踪……动辄几十万 Token。Agent 的上下文窗口就这么大，全塞进去就炸了。

TencentDB Agent Memory 用了一个巧妙的方法：符号化记忆（Symbolic Memory）。

冗长日志（几十万Token） │ ├── 1. 全文卸载到外部文件 (refs/*.md) │ ├── 2. 提取关系，生成 Mermaid 符号图 │ ├── 3. 轻量注入上下文（几百Token） │ └── 4. Agent 按需通过 node_id 精准检索原始文本

工作流程：

  1. 把冗长的工具输出卸载到外部文件

  2. 只在上下文里注入一张轻量级 Mermaid 符号图（几百 Token）

  3. Agent 基于符号图推理

  4. 需要查细节时通过 node_id 精准检索原始文本

这就像给 Agent 画了一张”任务地图”——它知道每一步做了什么、结果是什么，但不需要把所有细节都装在脑子里。需要的时候，按图索骥去翻就行。

四、硬核数据：省钱又提效

不是概念，是实打实的评测数据。TencentDB Agent Memory 在四个公开评测集上同时跑通了两条曲线：Token 下降，完成率上升。

划重点：

  • WideSearch：省了 61% Token，成功率还涨了 **51%**——省钱又提效，这谁顶得住？

  • PersonaMem：准确率从 48% 飙到 **76%**——意味着 AI 更懂你了

  • SWE-bench：跑 50 个连续编程任务，Token 省了 **33%**，通过率还涨了 10%

所有测试都是长会话连续任务（比如 SWE-bench 一次跑 50 个），不是单轮测试。这才反映真实生产环境的压力。

五、vs 竞品：为什么腾讯的做法不同？

目前市面上的 Agent 记忆方案主要分三类：

方案 代表 特点 问题
暴力截断 直接截断历史 简单粗暴 信息丢失，Agent 变傻
平面向量库 Mem0 / 传统 RAG 存一堆碎片 搜索无方向，召回不准
知识图谱 Zep (Graphiti) 时间维度建模 依赖云服务，成本高

TencentDB Agent Memory 的差异化在于：

  1. 分层而非平面——不是把所有记忆拍平到一个向量库，而是有层级、有结构

  2. 本地优先——数据不出你的机器，SQLite + sqlite-vec 后端，零外部依赖

  3. 符号化压缩——用高密度的 Mermaid 图代替冗长日志，不是暴力截断

  4. 全链路可追溯——每条记忆都能溯源到原始证据，不是”黑箱推荐”

  5. MIT 开源——不是”免费增值”，是真正的完全开源

用一句话说区别：别的方案是”记住更多”，这个方案是”推理更好”。

六、安装：两行命令搞定

OpenClaw 用户（推荐）

openclaw plugins install @tencentdb-agent-memory/memory-tencentdb openclaw gateway restart

默认使用本地 SQLite + sqlite-vec 后端，不需要任何外部 API。安装后自动启用对话捕获、记忆提取、场景聚合、画像生成。

Hermes 用户（Docker）

docker run -d \ --name hermes-memory \ --restart unless-stopped \ -p 8420:8420 \ -e MODEL_API_KEY="your-key" \ -e MODEL_BASE_URL="https://api.lkeap.cloud.tencent.com/v1" \ -e MODEL_NAME="deepseek-v3.2" \ -v hermes_data:/opt/data \ agentmemory/hermes-memory:latest

内置腾讯云 DeepSeek-V3.2 默认配置，开箱即用。

七、谁应该用？

适合你，如果你：

  • 用 AI Agent 做长任务（编程、调研、文档分析），经常遇到上下文爆炸

  • 在意 Token 成本，想让 Agent 跑得更便宜

  • 需要 Agent 记住你的工作习惯和偏好，不想每次都重新解释

  • 对数据隐私有要求，不想把对话历史上传到第三方

可能不适合，如果你：

  • 只做单轮问答，不需要跨会话记忆

  • 已经有成熟的记忆方案在跑

  • 不用 OpenClaw 或 Hermes

八、写在最后

2026 年，AI Agent 正从”能不能用”走向”能不能可靠地用”。而”记忆”是这条路上最关键的基础设施之一。

TencentDB Agent Memory 给出了一个优雅的答案：不是记住更多，而是记住对的。

记忆不是让 AI 记住一切，而是让人不用重复说一遍。
