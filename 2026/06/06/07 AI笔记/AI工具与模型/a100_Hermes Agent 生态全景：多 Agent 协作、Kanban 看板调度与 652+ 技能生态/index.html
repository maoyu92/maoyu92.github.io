Hermes Agent 生态全景：多 Agent 协作、Kanban 看板调度与 652+ 技能生态

一个人用一个 Agent 是效率工具，一群人用多个 Agent 是生产力系统。本文深入 Hermes Agent 的多 Agent 协作体系——Profiles 隔离、Kanban 看板调度、子 Agent 委托，以及覆盖 19+ 消息平台的完整生态版图。

多 Agent 管理：Profiles 系统

什么是 Profiles

Hermes v0.6.0 引入了 Profiles 系统，让你在一台机器上运行多个完全独立的 Agent。每个 Profile 拥有：

  • 独立的 config.yaml（配置）

  • 独立的 memory.md（记忆）

  • 独立的 skills/ 目录（技能）

  • 独立的 .env（API Key）

  • 独立的会话历史

就像给每个 Agent 一个独立的”人格”和”工作空间”。

创建和管理 Profile

# 创建新 Profile hermes profile create research # 创建时不带内置技能 hermes profile create research --no-skills # 切换到指定 Profile hermes profile use research # 查看当前 Profile hermes profile current # 列出所有 Profile hermes profile list # 删除 Profile hermes profile delete old-profile

实际使用场景

场景 1：工作分离

# 创建工作 Profile（编码专用） hermes profile create work hermes profile use work hermes model  # 配置编码模型（如 Claude Sonnet） # 创建研究 Profile（调研专用） hermes profile create research hermes profile use research hermes model  # 配置研究模型（如 Gemini）

场景 2：主 Agent 编排子 Agent

# 主 Profile 可以编排其他 Profile 的 Agent # 在 ~/.hermes/config.yaml 中配置 agents:   work_agent:     profile: work   research_agent:     profile: research   deploy_agent:     profile: deploy

主 Agent 通过 delegate_task 工具向子 Profile 的 Agent 分配任务。

Profile 隔离的好处

维度 效果
记忆隔离 工作记忆不会污染研究记忆
技能隔离 不同 Profile 安装不同技能
模型隔离 工作用 Claude，研究用 Gemini
配置隔离 不同的工具、平台、参数
上下文隔离 每个 Profile 的对话互不干扰

社区经验：

  • “第二个 Profile 不加任何个人数据，专门用于部署和修代码”

  • “默认的 memory.md 太小了，分 Profile 后每个都够用”

  • “一个主 Profile 编排所有其他 Profile——这是最强的工作流”

子 Agent 委托：delegate_task

工作原理

主 Agent 通过 delegate_task 工具生成隔离的子 Agent，每个子 Agent 拥有：

  • 独立的对话历史

  • 独立的终端会话

  • 独立的工具集

  • 完全隔离的执行环境

主 Agent（编排者） ├── 子 Agent 1（调研任务） │   └── 独立对话 + 工具 ├── 子 Agent 2（代码任务） │   └── 独立对话 + 工具 └── 子 Agent 3（测试任务）     └── 独立对话 + 工具

委托模式

顺序委托：主 Agent → 研究 Agent → 验证 Agent

# 主 Agent 在聊天中发起 请调研一下 Next.js 15 的新特性，然后验证关键功能是否可用

Hermes 会自动：

  1. 启动研究子 Agent 进行调研

  2. 调研完成后启动验证子 Agent

  3. 汇总结果返回给主 Agent

并行委托：同时调研 3 个主题

# 主 Agent 同时启动多个子 Agent 同时调研 A、B、C 三个方案的优劣

每个子 Agent 独立执行，结果汇总后由主 Agent 评分筛选。

安全审查模式

全新上下文审查：子 Agent 在完全隔离的上下文中审查代码，不受主 Agent 偏见影响。

# 主 Agent 生成代码后，委托子 Agent 审查 我刚写完了认证模块，请帮我审查代码质量 # Hermes 自动启动审查子 Agent

Kanban 看板：可视化任务调度

概述

Hermes 内置了一个 SQLite 单文件驱动的 Kanban 看板系统，实现多 Agent 协作的任务调度。

核心设计：

  • SQLite 单文件 = 唯一真相源

  • 卡片式任务管理

  • CLI + 工具双入口共享同一数据库

  • 自动依赖管理 + 自愈能力

看板结构

┌─────────┬──────────┬──────────┬─────────┐ │  Backlog │  Ready   │ Running  │  Done   │ ├─────────┼──────────┼──────────┼─────────┤ │  任务 A  │  任务 B  │  任务 C  │  任务 D  │ │  任务 E  │  任务 F  │          │  任务 G  │ └─────────┴──────────┴──────────┴─────────┘

工作流程

  1. 创建卡片：用户或 Agent 创建任务卡片

  2. 分配 Profile：指定由哪个 Profile 的 Agent 执行

  3. 依赖管理：设置父子任务关系

  4. Dispatcher 循环：

    • 扫描 Ready 列中的就绪卡片

    • 分配给指定 Profile 的 Agent

    • Agent 执行任务

    • 完成后自动推进到下一阶段

  5. 自动依赖推进：父任务完成后，子任务自动变为 Ready

  6. 并行执行：多个 Agent 同时处理不同卡片

  7. 自愈：任务失败时自动恢复

实际案例

社区用户分享的生产级工作流：

Scout Agent（X + Reddit 数据采集）     ↓ Orchestrator（评分筛选）     ↓ Researcher × 3（并行验证：技术可行性 / 商业模式 / 竞品分析）     ↓ Builder + Tester（代码实现 + 测试）     ↓ 人类审批（最后环节）

结果：18 个 Agent 并行运行，97 个任务完成，人类只在最后审批环节介入。

CLI 命令

# 查看看板 kanban list # 创建任务 kanban add "实现用户认证" --profile work --priority high # 任务状态流转 kanban move <task-id> running kanban move <task-id> done # 查看 Agent 状态 kanban agents

上手建议

新手路径

  1. 安装：curl -fsSL https://res1.hermesagent.org.cn/install.sh | bash（国内镜像）

  2. 配置：hermes setup（交互式向导）

  3. 选模型：hermes model（推荐 OpenRouter）

  4. 开始聊天：hermes

  5. 探索技能：/skills

进阶路径

  1. 配置消息平台：hermes gateway setup

  2. 创建多 Profile：hermes profile create work

  3. 安装技能：hermes skills install <name>

  4. 尝试 Goal 系统：/goal 完成 XXX 任务

  5. 探索 Kanban：多 Agent 并行工作

生产级路径

  1. VPS 部署：Docker 容器化

  2. 多 Profile 编排：主 Agent + 专业子 Agent

  3. Kanban 看板：可视化任务调度

  4. 自定义技能：为你的业务创建专属技能

  5. 安全配置：命令审批、权限分级

小结

Hermes Agent 不只是一个聊天工具——它是一个完整的自我进化 Agent 平台。从单机多 Profile 隔离，到 Kanban 看板的可视化调度，再到 652+ 技能的生态支撑，它正在重新定义”AI 助手”的边界。

与 OpenClaw 的对比不是”谁更好”，而是”谁更适合你的场景”：

  • 需要精细任务控制 + 自我进化 → Hermes

  • 需要消息网关 + 快速接入 → OpenClaw

  • 需要多 Agent 协作 → 两个都行，但 Hermes 的 Kanban 更直观

不管选哪个，AI Agent 的时代已经来了。
