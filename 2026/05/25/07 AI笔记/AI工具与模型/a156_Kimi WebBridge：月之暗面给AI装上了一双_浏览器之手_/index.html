Kimi WebBridge：月之暗面给AI装上了一双"浏览器之手"

引言

AI 编程助手能帮你写代码、改 bug、读文档，但你是否遇到过这样的困境——

“

“帮我查一下京东上 iPhone 15 的价格” “帮我抓取这个小红书账号最近 10 篇爆文的标题和点赞数” “帮我登录这个量化平台，导出最近一周的资金流向数据”

不好意思，AI 做不到。这些任务必须在浏览器里完成，AI 助手够不着。

直到现在。

Kimi WebBridge，月之暗面 2026 年 5 月中旬正式发布的一款浏览器插件，让 AI Agent 能像真人一样操作你的 Chrome 或 Edge——用的是你的登录态、你的 Cookie、你的账号。

这意味着，在目标网站看来，AI 就是你本人。

一、它究竟是什么

Kimi WebBridge 是月之暗面（Moonshot AI）推出的一款浏览器扩展，扮演 AI Agent 与浏览器之间的”桥梁”角色。

官方给它的定位是：

“

“让 AI 帮你打开网页、点击按钮、填写表单、提取信息，为你自动化各种繁琐的网页操作。”

但实际上，它的野心远比”自动化表单”大得多——它的本质是：给 AI Agent 装上了一双可以操控浏览器的手和眼睛。

二、技术原理：本地优先，数据不离开设备

Kimi WebBridge 的架构分为两个组件：

组件 作用
本地桥接服务（Daemon） 接收 AI Agent 的指令，调度 Chrome DevTools Protocol
浏览器扩展（Extension） 基于 Chrome DevTools Protocol 在你的浏览器里完成实际操作

数据流向是这样的：

AI Agent → 本地桥接服务 → Chrome DevTools Protocol → 你的 Chrome/Edge 浏览器                                     ↓                               执行结果返回 Agent

关键特性：所有操作都在本地完成。 你的登录态、Cookie、页面内容不会离开你的设备。这与 OpenAI Operator 等云端方案形成了本质差异。

技术后盾是月之暗面自研的 Kimi K2.6 模型（2026 年 4 月发布），在 SWE-Bench Pro 基准测试中得分 58.6%，超越了 GPT-5.4（57.7%）和 Claude Opus 4.6（53.4%）。K2.6 支持最多 300 个并行子 Agent，是 WebBridge 处理复杂多步骤浏览器任务的基础。

三、支持哪些 AI Agent

Kimi WebBridge 并不绑死月之暗面自己的产品，它面向整个 AI Agent 生态：

  • ✅ Kimi Code（月之暗面自家）

  • ✅ Claude Code（Anthropic）

  • ✅ Cursor（AI 代码编辑器）

  • ✅ Codex（OpenAI）

  • ✅ Hermes Agent

  • ✅ OpenClaw（你正在用的这个！）

也就是说，不管你用什么 AI 编程助手，只要它支持 Skill 或命令行调用，理论上都可以连接 WebBridge。

四、它能做什么？5个真实场景

场景 1：社媒热点选题

让 Agent 自动打开微博、知乎、小红书，爬取指定话题下的热门内容，整理成表格：

“

“帮我采集小红书、抖音和快手在 App Store 的评分和简介”

手动操作约 30 分钟 → AI 自动执行约 3 分钟

场景 2：求职信息收集

“

“帮我去猎聘上搜索 ‘AI 工程师’，上海，薪资 30K 以上，把前 20 条的职位名、公司名、薪资整理成表格”

Agent 自己翻页、提取、汇总，不用你一条条复制粘贴。

场景 3：金融量化数据抓取

“

“帮我登录聚宽量化平台，获取最近一周沪深 300 成分股的资金流向数据，导出 CSV，然后写一份简要分析报告”

这是传统 RPA 工具很难优雅完成的任务——需要登录态、需要翻页、需要导出文件。WebBridge 完美解决。

场景 4：竞品价格监控

“

“每天早上 9 点，帮我抓取京东和天猫上 iPhone 15 的价格”

可以进一步结合定时任务，实现完全自动化的价格监控。

场景 5：跨平台内容整合

让 Agent 带着你的账号去各个网站执行任务——发帖、评论、数据采集——而不需要任何第三方 API。

五、安装配置：3 步搞定

第一步：安装浏览器扩展

在 Chrome 应用商店或 Edge 插件商店搜索 **”Kimi WebBridge”**，点击安装。

「Chrome 应用商店安装界面示意」（可在 Chrome Web Store 搜索 “Kimi WebBridge” 找到）

（如果网络访问困难，也可以手动下载安装，官方提供了离线包：https://cdn.kimi.com/webbridge/latest/releases/）\[1\]

第二步：安装本地桥接服务

在终端运行：

curl -fsSL https://kimi-web-img.moonshot.cn/webbridge/install.sh | bash

安装完成后可通过以下命令检查状态：

kimi-webbridge status

第三步：连接你的 AI Agent

以 OpenClaw 为例，直接发送：

“

“使用 kimi-webbridge 帮我打开 kimi.com”

如果浏览器成功打开了 kimi.com 标签页并出现 agent:kimi 提示，说明连接成功 🎉

WebBridge 的核心优势是跨越了数字身份的鸿沟——传统工具需要自己维护登录态，而 WebBridge 直接继承了你浏览器里已有的身份，让 AI 能以你的真实身份在网页世界中自主行动。

七、为什么它值得你关注

1. 数据隐私优先

在这个 AI Agent 疯狂访问你数据的时代，本地优先是一个重要的信任信号。WebBridge 的设计确保了你的账号、Cookie、页面内容不会流经任何第三方服务器。

2. 真正的”真人级”操作

与需要手动维护 Session 的传统方案不同，WebBridge 直接使用你当前的浏览器状态。对目标网站来说，这就是你本人在操作。

3. 降低 AI Agent 的能力天花板

过去 AI Agent 的能力边界止步于”无法触碰浏览器”——这限制了它在办公自动化领域的发挥空间。WebBridge 补上了这关键一环。

4. 生态开放，不锁死

月之暗面没有把 WebBridge 做成 Kimi 独占，而是选择支持所有主流 AI Agent。这是明智的生态策略，也让更多用户能从中受益。

八、局限性与注意事项

  • 需要你的浏览器处于运行状态：WebBridge 操控的是你现有的浏览器，而不是无头浏览器

  • 复杂交互任务仍需调教：AI Agent 操作浏览器需要探索和迭代，固定流程越清晰，执行效率越高

  • 部分网站有反爬机制：登录态并不能规避所有反爬策略，高强度爬取仍需谨慎

  • 定时任务需要配合系统级调度：WebBridge 本身不提供定时执行能力，需结合系统任务或 Agent 的计划功能

结语

Kimi WebBridge 的出现，填补了 AI Agent 在”浏览器操作”这个关键环节的能力空白。

它不是第一个浏览器自动化工具，但它是第一个真正面向 AI Agent 生态、本地优先、零配置门槛的方案。

当 AI 能像你一样操作浏览器的那一刻，办公自动化的边界正在被重新定义。

如果你也在用 AI Agent 办公，强烈建议去体验一下 Kimi WebBridge。 你会发现，AI 辅助办公的体验直接跃升好几个档次。
